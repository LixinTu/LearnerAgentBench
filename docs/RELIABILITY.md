# Benchmark reliability — what is guarded and how

Each concern below has a test that fails if the guarantee is broken. Run `pytest tests/integration/test_reliability.py tests/integration/test_independent_plan_checker.py tests/e2e/test_negative_cases.py`.

| concern | guarantee | where it is tested |
|---|---|---|
| Oracle and verifier sharing logic | The reference path proves satisfiability but the structural plan rules are re-implemented from scratch in a test and must agree with `PlanOracle.assess` on oracle plans and on hand-made bad plans. The learner model is shared by design (it is the environment's ground truth) and is documented as such. | `test_independent_plan_checker.py` |
| Hidden answers reaching the agent | The agent's first observation (`TaskView`) may only contain run/task ids, the goal, time, instructions, persona summary, gated memory/history and tool schemas; no observation in an oracle run contains the words `hidden_constraints`, `verifier`, `check_id`, `reference_replies`, `negative_cases`, `reference_path`, `scripted_replies`, `expected_delta`, `rubrics`; the request never restates a hidden constraint. | `test_reliability.py::test_agent_inputs_contain_no_grading_material` |
| Tool calls change state | A `create_task` call leaves a todo in the final world and passes the check; a final message claiming the same leaves nothing and fails it. | `test_reliability.py::test_tool_calls_change_state_and_claims_do_not` |
| Talk without action | On every task, an agent that only says it did everything scores ≤ 50% and fails; an agent that does nothing fails a hard check. | `test_negative_cases.py` |
| Permission violations, duplicates, ignored events | Declared negative cases per task: forbidden attempts show up in `authorization_violations`, identical writes in `duplicate_actions`, event-ignoring plans fail `event.state_after` / window checks. Verifiers read the audit log, never the agent's text. | `test_negative_cases.py::test_declared_negative_case`, `tests/unit/test_tools.py` |
| Pre-existing state passing as work | Seeded plans/records (last week's plan, an old task) cannot satisfy checks tagged `written_this_run`; only a successful tool call of this run that wrote the record counts. `event.state_after` counts agent writes at or after the event's delivery step, so a seeded record whose timestamp equals the event's (the clock does not move before step 0) no longer passes. A talk-only agent fails these on B02, D03 and E05. | `test_reliability.py::test_records_that_predate_the_session_do_not_satisfy_outcome_checks`, `::test_event_state_after_counts_only_agent_writes_after_delivery` |
| Oracle runs that succeed by accident | `lab validate --oracle` fails a task whose oracle run has environment errors or any attribution other than `none` (caught a calendar-change event that crashed on string dates while the checks still passed). | `tests/unit/test_runtime_loop.py::test_calendar_change_update_parses_string_dates_and_records_the_step` |
| Reproducibility | Two oracle runs with the same seed produce identical check outcomes, scores, plan blocks, record counts and action sequences; `lab reverify` re-scores a run from its snapshots; LLM adapters pass `seed` and temperature 0 (model-side determinism is the provider's). | `test_reliability.py::test_oracle_runs_reproduce`, `tests/e2e/test_runner_oracle.py` |
| Environment vs agent failure | An internal tool exception or an outage the task did not inject → `failure_attribution = environment`; an injected outage → `agent`; adapter/API errors → `model_api`; unverifiable checks → `harness`. Timezone-suffixed timestamps from the model are now a validation error (agent), not a crash. | `test_reliability.py` |
| Environment crashes charged to the environment | Arguments a weak model is likely to send — an empty skill list, a course *code* instead of its id, timezone suffixes — are validation / not-found errors with a usable message, never internal exceptions (the first local sweep crashed `record_learning_progress` on `skill_ids: []`). | `tests/unit/test_tools.py::TestEnvironmentFairness`, `test_reliability.py::test_bad_arguments_are_the_agents_fault_not_the_environments` |
| Silent empty results | A filter on an unknown course raises `not_found` listing the known courses instead of returning `[]`, which the agent read as "no results" and reported to the student (B01 in the baseline sweep). | `TestEnvironmentFairness::test_course_filters_accept_the_code_and_reject_unknown_courses` |
| Half-done tool calls | A mutating tool that raises after writing restores the world — records *and* history — to the state before the call; the audit row carries no touched records and `mutated=False`. | `TestEnvironmentFairness::test_a_tool_that_fails_half_way_leaves_no_trace` |
| Sweep tables group by what the experiment varied | `lab summarize --group-by condition,family` reads the condition / family from each run's `config.json` and `task_effective.json`, so a table never shows `?` for a sweep run. | `tests/unit/test_analysis_summary.py` |
| Counterfactual patches that silently do nothing | A variant whose `memory_remove` / `memory_replace` names a memory id that is not in the world raises `NotFoundError` at world build (so `lab validate` fails) instead of skipping it: D04's `standing_rule_instead` had carried a stale id for weeks and was quietly running with both the old one-off and the new rule. Under `no_memory` the ids are tolerated because everything is gone already. | `tests/unit/test_variants_strict.py` (incl. a scan of every dataset variant) |
| An event the agent never reached | `event.state_after` / `event.responded_with_tool` on a time-triggered event that is in the task's timeline but never fired because the episode ended first now *fail* (the agent was told to wait, as in D06) instead of coming back unverified and charged to the harness; an event id the task does not know stays unverified. Step-triggered events still fire after the agent finishes. | `tests/unit/test_event_verifiers_unreached.py` |
| A rule that changes mid-tutoring | `tutoring.hint_policy` takes `policy_after_event`: every tutor turn taken at or after the loop step at which that event was delivered is judged by the new policy, earlier turns by the old one, and all turns by the old one if the event never fired — so the expected behaviour follows the agent's own timeline rather than a fixed turn index (C07). | `tests/unit/test_tutoring_policy_switch.py` |

What the agent *can* learn from the environment on purpose: its own profile, preferences and memory (through tools or the prompt depending on the baseline), assessments and results, the calendar, inbox, plans, tasks, and the LMS's knowledge estimate per skill (`analyze_skill_gaps`). None of these contain the task's checks or expected outcomes.

Known limits: regex-based checks on free text (final messages, tutoring turns) can miss paraphrases — they are tagged, carry evidence, and are never the only hard check on a task; one seed per task so far.
