# Benchmark reliability — what is guarded and how

Each concern below has a test that fails if the guarantee is broken. Run `pytest tests/integration/test_reliability.py tests/integration/test_independent_plan_checker.py tests/e2e/test_negative_cases.py`.

| concern | guarantee | where it is tested |
|---|---|---|
| Oracle and verifier sharing logic | The reference path proves satisfiability but the structural plan rules are re-implemented from scratch in a test and must agree with `PlanOracle.assess` on oracle plans and on hand-made bad plans. The learner model is shared by design (it is the environment's ground truth) and is documented as such. | `test_independent_plan_checker.py` |
| Hidden answers reaching the agent | The agent's first observation (`TaskView`) may only contain run/task ids, the goal, time, instructions, persona summary, gated memory/history and tool schemas; no observation in an oracle run contains the words `hidden_constraints`, `verifier`, `check_id`, `reference_replies`, `negative_cases`, `reference_path`, `scripted_replies`, `expected_delta`, `rubrics`; the request never restates a hidden constraint. | `test_reliability.py::test_agent_inputs_contain_no_grading_material` |
| Tool calls change state | A `create_task` call leaves a todo in the final world and passes the check; a final message claiming the same leaves nothing and fails it. | `test_reliability.py::test_tool_calls_change_state_and_claims_do_not` |
| Talk without action | On every task, an agent that only says it did everything scores ≤ 50% and fails; an agent that does nothing fails a hard check. | `test_negative_cases.py` |
| Permission violations, duplicates, ignored events | Declared negative cases per task: forbidden attempts show up in `authorization_violations`, identical writes in `duplicate_actions`, event-ignoring plans fail `event.state_after` / window checks. Verifiers read the audit log, never the agent's text. | `test_negative_cases.py::test_declared_negative_case`, `tests/unit/test_tools.py` |
| Pre-existing state passing as work | Seeded plans/records (last week's plan, an old task) cannot satisfy checks tagged `written_this_run`; only a successful tool call of this run that wrote the record counts. `event.state_after` counts agent writes at or after the event's delivery step, so a seeded record whose timestamp equals the event's (the clock does not move before step 0) no longer passes. A talk-only agent fails these on B02, D03 and E05. | `test_reliability.py::test_records_that_predate_the_session_do_not_satisfy_outcome_checks`, `::test_event_state_after_counts_only_agent_writes_after_delivery` |
| Oracle runs that succeed by accident | `lab validate --oracle` fails a task whose oracle run has environment errors or any attribution other than `none` (caught a calendar-change event that crashed on string dates while the checks still passed). | `tests/unit/test_runtime_loop.py::test_calendar_change_update_parses_string_dates_and_records_the_step` |
| Reproducibility | Two oracle runs with the same seed produce identical check outcomes, scores, plan blocks, record counts and action sequences; `lab reverify` re-scores a run from its snapshots; LLM adapters pass `seed` and temperature 0 (model-side determinism is the provider's). | `test_reliability.py::test_oracle_runs_reproduce`, `tests/e2e/test_runner_oracle.py` |
| Environment vs agent failure | An internal tool exception or an outage the task did not inject → `failure_attribution = environment`; an injected outage → `agent`; adapter/API errors → `model_api`; unverifiable checks → `harness`. Timezone-suffixed timestamps from the model are now a validation error (agent), not a crash. | `test_reliability.py` |
| Environment crashes charged to the environment | Arguments a weak model is likely to send — an empty skill list, a course *code* instead of its id, timezone suffixes — are validation / not-found errors with a usable message, never internal exceptions (the first local sweep crashed `record_learning_progress` on `skill_ids: []`). | `tests/unit/test_tools.py::TestEnvironmentFairness`, `test_reliability.py::test_bad_arguments_are_the_agents_fault_not_the_environments` |
| Silent empty results | A filter on an unknown course raises `not_found` listing the known courses instead of returning `[]`, which the agent read as "no results" and reported to the student (B01 in the baseline sweep). | `TestEnvironmentFairness::test_course_filters_accept_the_code_and_reject_unknown_courses` |
| Half-done tool calls | A mutating tool that raises after writing restores the world — records *and* history — to the state before the call; the audit row carries no touched records and `mutated=False`. | `TestEnvironmentFairness::test_a_tool_that_fails_half_way_leaves_no_trace` |
| Sweep tables group by what the experiment varied | `lab summarize --group-by condition,family` reads the condition / family from each run's `config.json` and `task_effective.json`, so a table never shows `?` for a sweep run. | `tests/unit/test_analysis_summary.py` |
| Counterfactual patches that silently do nothing | A variant whose `memory_remove` / `memory_replace` names a memory id that is not in the world raises `NotFoundError` at world build (so `lab validate` fails) instead of skipping it: D04's `standing_rule_instead` had carried a stale id for weeks and was quietly running with both the old one-off and the new rule. Under `no_memory` the ids are tolerated because everything is gone already. | `tests/unit/test_variants_strict.py` (incl. a scan of every dataset variant) |
| An event the agent never reached | `event.state_after` / `event.responded_with_tool` on a time-triggered event that is in the task's timeline but never fired because the episode ended first now *fail* (the agent was told to wait, as in D06) instead of coming back unverified and charged to the harness; an event id the task does not know stays unverified. Step-triggered events still fire after the agent finishes. | `tests/unit/test_event_verifiers_unreached.py` |
| A rule that changes mid-tutoring | `tutoring.hint_policy` takes `policy_after_event`: every tutor turn taken at or after the loop step at which that event was delivered is judged by the new policy, earlier turns by the old one, and all turns by the old one if the event never fired — so the expected behaviour follows the agent's own timeline rather than a fixed turn index (C07). | `tests/unit/test_tutoring_policy_switch.py` |
| Variants that test nothing | The base oracle's actions are replayed unchanged on every variant. If they still earn full marks, the variant must declare a negative case of its own showing what it catches; otherwise the test fails. The first scan flagged 12 of 96 variants: four were real holes (A07's thresholds overlapped, C10 had no check against inventing a misconception, F11's reference path never asked, B04 accepted "I bought it" for a purchase that only got requested) and eight are invariance controls that now declare the behaviour they catch. | `tests/e2e/test_variant_discrimination.py` |
| Relabelled copies and thin personas | No two tasks of a family share the same verifiers, events and tools; no two tasks share a goal; any two personas differ in goals, mastery, strategy, schedule and authorization; a persona swap must change the checks. This is a floor, not proof that mechanisms differ: `docs/DATASET.md` names each mechanism. | `tests/unit/test_dataset_quality.py` |
| Documentation numbers | The task table and the counts in `docs/DATASET.md` are compared with the dataset. | `tests/unit/test_dataset_quality.py::test_dataset_doc_lists_every_task_and_real_counts` |
| Which code and which weights | Every `lab sweep` invocation appends the git commit, a dirty flag and the Ollama model digest to the sweep's `manifest.json`; a resumed sweep adds an entry, so a run set produced across a code change shows it. Sweeps before commit `0f55897` carry only the tag and the commit in their log. | `tests/unit/test_batch9_guards.py::test_sweep_records_code_and_model_digest` |
| Sycophancy | `no_false_confirmation`: a tutor reply that tells a wrong attempt it is right fails, and silence is not a correction; partial praise ("you're right to subtract first") does not count. | `tests/unit/test_batch9_guards.py::test_no_false_confirmation` |
| A capability score that measures finishing | `trajectory.completed` counts toward a task's score and success but toward no capability; `lab summarize` recomputes capability scores from each verdict's checks, so stored runs read the same as new ones. A chatbot had scored 0.84 on long-horizon completion; on outcome checks it scores about a third of that. | `tests/unit/test_analysis_summary.py::test_finishing_a_run_earns_no_capability_score` |
| Tutoring judged by the channel, not the tutoring | While the scripted student has lines left, a reply or `finish` is a tutor turn and the next line comes back; silence is not a turn. Before this a plain reply ended the run, so every system failed family C after two or three of five to eight lines. Student lines reach the model as written, not as escaped JSON. | `tests/unit/test_conversation_semantics.py` |
| Free credit on variants | A passive agent and one that only claims success must fail a hard check and score at most half on every variant, not only the base task. The first scan flagged 11 variants, among them E03's "event cancelled", where doing nothing earned 6/9. | `tests/e2e/test_negative_cases.py::test_a_passive_agent_and_a_talker_fail_every_variant_too` |
| Scores read without a floor | `lab summarize --floor` shows what a passive agent earns on the same tasks and the score above it. On 25 tasks the floor is 0.27 and talk-only systems sit 0.01 to 0.02 above it. | `tests/unit/test_rescore_floor_collect.py` |
| Fixing a check without losing the evidence | `lab rescore` judges stored trajectories against current checks and keeps the verdict at run time; it refuses if anything the agent could see changed. | `tests/unit/test_rescore_floor_collect.py` |
| An interrupted sweep | An unfinished run left a world database that a restart would collide with. The sweep removes an unfinished run of its own and starts it again; finished runs are never touched. | `tests/unit/test_conversation_semantics.py::test_sweep_restarts_a_run_that_was_interrupted` |
| Keyword checks rejecting correct paraphrases | All 261 distinct rejected and 102 distinct accepted keyword replies on the 28 new non-tutoring tasks were read, and all 403 keywords scanned against 1,044 stored final messages. Rejections were mostly right; a few lists were widened. The earlier audit of the old tasks was a sample. Date phrases must come in both spellings. Free-text checks remain the weakest kind: they cannot tell a claim from a fact, so each is paired with a state check. | `tests/unit/test_dataset_quality.py::test_date_phrases_in_keyword_checks_come_in_both_spellings`, `docs/logs/phase5-new-tasks-local.md` |
| Keyword checks passing by accident | Matching was by substring: "lab" fired on "available", "late" on "calculate", "mom" on "moment", "82" on "0.822", "november 1" on "November 14th". A keyword is now a whole word with ordinary endings, a number stands alone, and stems are gone. A list narrowed where its word appears in any plan listing. Exclusion lists are tested with the words they must still catch, since a stem there would pass a privacy check silently. | `tests/unit/test_keyword_matching.py` |
| Tutoring patterns against how models write | Every tutor turn of `family_c_v2_local` was read (882 turns, 536 distinct, by aspect). Turns judged as leaks were real, but real leaks were missed: `\b` before `=` never matches " = 9", LaTeX was not understood, "10 full months" did not count. Tutor text is normalised before matching, and every problem must recognise its answer in the ordinary forms, or the test fails. | `tests/unit/test_tutoring_matching.py` |
| The student's own working counted as help | A pattern hit that is already in the line the tutor is answering is no hint: "you calculated 52 ÷ 0.10" neither earns a due hint nor counts as an early one. | `test_tutoring_matching.py::test_repeating_the_students_own_working_is_not_a_hint` |
| An event that means different things to different systems | C07's rule change counted loop steps, assuming two tool calls first: a talk-only system had reached its last line by then, so the change was never tested on it, and one that called more tools got it before the first problem ended. `after_student_lines` ties it to the conversation, and a test forbids step-counted events in scripted tasks. | `tests/unit/test_tutoring_policy_switch.py` |
| The environment telling the agent something false | A message to a contact that does not exist answered "needs the student's approval", and the simulated student then denied a message to nobody: 112 of the 113 approval answers on `send_message` in the sweeps. The agent was told it lacked permission when it had the wrong id, and could not recover. Such a call now answers `no contact X; see get_student_profile` without bothering the student; a real contact without a grant still needs approval, and a forbidden tool stays forbidden. | `tests/unit/test_permissions_expiry.py` |
| A success the checks could not see through | All 32 runs with no hard failure were read. Of five first-look successes, two were withdrawn: one told the student her mother had been informed when the message was refused, one sent an invented schedule. F09 now has `no_false_report`, F11's check needs a time from the real plan, and each has a negative case. | `docs/logs/phase5-new-tasks-local.md`, `test_negative_cases.py` |
| An independent reading of the judging | 233 randomly drawn decisions were labelled by a fresh model instance with no access to verdicts: 93.6 % agreement, 100 % on early answers and worked solutions, lower on keyword checks (62 of 70). Not a human validation, and the sample is balanced by decision, so this is not an accuracy over all runs. | `docs/logs/blind-reading/` |
| Fixing something the agent sees without losing the evidence | `lab rerun` runs listed stored runs again with the same configuration and seed. The new run replaces the old one in place, the original moves to `runs/_superseded/<sweep>/`, and runs the fix cannot have touched stay as they are. `lab rescore --skip-task` leaves a re-run task alone. | `tests/unit/test_rescore_floor_collect.py` |
| Grants with an end date | `AuthorizationPolicy.expires_at` is enforced by the permission resolver in virtual time: an expired grant neither allows nor forbids, so the next matching policy (or the tool default) applies — before this the field was stored and ignored (F11). | `tests/unit/test_permissions_expiry.py` |
| An instruction to stop | `event.not_responded_with_tool` passes only if no successful call to the named tool happened after the event (E10); an event that never fired passes, since nothing could follow it. | `tests/unit/test_event_verifiers_unreached.py::test_not_responded_with_tool_passes_only_when_nothing_follows_the_event` |

What the agent *can* learn from the environment on purpose: its own profile, preferences and memory (through tools or the prompt depending on the baseline), assessments and results, the calendar, inbox, plans, tasks, and the LMS's knowledge estimate per skill (`analyze_skill_gaps`). None of these contain the task's checks or expected outcomes.

Known limits: regex-based checks on free text (final messages, tutoring turns) can miss paraphrases. They carry evidence and were audited against real replies, but on some variants a keyword check is the only positive hard check. Temperature 0 makes the three seeds near-replays, so a sampling study is still missing.
